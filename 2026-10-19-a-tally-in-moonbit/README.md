# The same tally, in MoonBit

The service from the 2026-10-16 example, unchanged, composed with a `tally` component written in [MoonBit](https://www.moonbitlang.com/) instead of Rust. `service/` is the Rust Compute service. `tally/` is a MoonBit project that exports the `tally` resource and keeps its own handle table. `wac plug` composes them into one component whose imports are all in Compute's `service` world.

Full article: [The Same Tally, in MoonBit](https://behindthepanic.dev/posts/2026-10-19-a-tally-in-moonbit/)

## Prerequisites

- Rust with the `wasm32-wasip2` target: `rustup target add wasm32-wasip2`
- The [MoonBit toolchain](https://www.moonbitlang.com/download/) (`moon`)
- [`wasm-tools`](https://github.com/bytecodealliance/wasm-tools) and [`wac`](https://github.com/bytecodealliance/wac), which the build script uses to make the MoonBit component and compose the two
- The [Fastly CLI](https://github.com/fastly/cli) (`brew install fastly/tap/fastly`), which bundles Viceroy for local serving

## Run it

```sh
fastly compute serve
curl http://127.0.0.1:7676/
```

The response is `bytes reached 42`, and Viceroy's log shows each `tally` being created and dropped, the same five lines the all-Rust version printed.

## The generated bindings, and the one hand-patched line

Everything under `tally/gen/`, `tally/interface/`, and `tally/world/` was generated by `wit-bindgen moonbit` 0.62.0 from `wit/world.wit`:

```sh
wit-bindgen moonbit wit --world tally-provider --out-dir tally
```

and then migrated to MoonBit's current project format with `moon fmt`. Two files in `tally/gen/interface/local/main/tally/` are not generated output:

- `stub.mbt` is the implementation: the `State` struct, the rep-to-state table, and the three functions the bindings declare.
- `moon.pkg` adds the imports `stub.mbt` uses (`wasi:cli/stderr` and MoonBit's UTF-8 encoder).

One file is generated but patched by hand. In `ffi.mbt`, the constructor lifts `name` with `mbt_ffi_ptr2bytes` and `@utf8.decode_lossy` instead of the generated `mbt_ffi_ptr2str`. The generated glue assumes UTF-16 strings, which is what MoonBit's own component tutorial builds with (`wasm-tools component embed --encoding utf16`). A component built that way runs in Viceroy, but uploading it to a real Compute service failed with `Failed to extract metadata from package`. The build script here uses `--encoding utf8`, which uploads and deploys, and the patch makes the glue match it.

If you regenerate the bindings, reapply that patch, or the constructor will read UTF-8 bytes as UTF-16 code units.

Use wit-bindgen 0.62.0 or later. Bindings generated by 0.57.1 crashed inside MoonBit's allocator with the current MoonBit compiler.
